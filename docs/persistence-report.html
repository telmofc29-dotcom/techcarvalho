Stage modes: root cause & fix

v1 wrote this:

check (... and not exists (
  select 1 from jsonb_each_text(stage_modes) as m(key, value)
  where m.value not in ('MANUAL','ASSISTED','AUTOMATIC')
))

PostgreSQL rejects it with 0A000. A CHECK expression must be a scalar expression over the row — no subqueries, no set-returning functions in a FROM clause — because it is evaluated row-by-row without a query plan. The mistake was reaching for relational syntax to express a per-element rule over a JSON value.

The fix: the whole rule moves into one IMMUTABLE function and the constraint becomes a single call. A CHECK may call a function; the prohibition is on subqueries in the constraint expression, not inside the function it calls.

A cleverer version I deliberately threw away

I first rewrote it with jsonpath predicates (stage_modes @? '$.* ? (…)'), which are operators and therefore also legal in CHECK. I abandoned it: jsonpath defaults to LAX mode, which auto-unwraps arrays inside filters, so {"briefs": ["MANUAL"]} plausibly slips through a per-value check. Getting it right needs strict mode plus knowing how @? suppresses structural errors — and there is no PostgreSQL in this environment to test against. I am not willing to ship a constraint whose correctness rests on semantics I cannot execute. Plain SQL over jsonb_each_text is duller and I can be sure of it by reading it.

Because I cannot execute it, the migration proves itself. It carries 18 assertions in a DO block that run at apply time. If my reasoning is wrong the transaction raises and rolls back, so a broken constraint cannot be left installed.

The {"briefs": null} case is worth calling out: jsonb_each_text turns a JSON null into SQL NULL, NULL = any(...) is NULL, and bool_and would swallow that into a NULL result that coalesce then turns into TRUE. An explicit is not null guard closes it.

SAFE TO APPLY: YES

The 0A000 cause is removed, and the migration validates itself on the way in. Applying it changes no behaviour — every stage resolves to ASSISTED before and after, which is what the engine already does.

Validating keys in the database means adding a stage now needs a one-line CREATE OR REPLACE FUNCTION. A test parses the stage array out of the SQL file and asserts it matches ENGINE_STAGE_NAMES, so the two cannot drift silently.

iPhone 18 went from 14 claims to 39, carrying real figures — a $100 increase, $1,199 pricing, RAM and NAND cost pressure — instead of headline fragments.

Nothing is bypassed. robots.txt is checked before the request, and a disallow means the article is never fetched at all — asking and then ignoring the answer would be worse than not asking. 403s, paywalls, consent walls and anti-bot challenges are each recorded as a refusal and left alone. There is no user-agent rotation, and there must not be one added.

An extraction yielding under 1200 characters is reported as summary_only, not as full text. A page that returns 300 characters is navigation and a consent banner, and calling that "fully researched" is the exact dishonesty this records against.

04

The owner package

A corroborated topic with no TechCarvalho coverage is now one queue row and one decision page at /admin/engine/topics/[id]: why now, research, recommendation, sources, and what was actually claimed.

Two things it refuses to blur:

  • Origins versus URLs. Collapsed sources are listed with the reason, so "4 sources" can never quietly mean one story repeated four times.
  • Article versus product. Separate verdicts, different bars. Rumours can justify a well-framed article long before they justify a catalogue page asserting a product exists.

Approving creates the brief, marks it approved, and calls the same assembly RPC the nightly stage calls. Hedged claims go to uncertainties, never verified_facts — a hedge cannot become a fact by passing through the action. Assembly still hard-wires status='draft', so approving never publishes.

One honest omission on the queue row

Content provenance is passed as null, not 0, because it is not yet persisted per evidence row — so the signal is omitted rather than shown. Understating provenance is as misleading as overstating it.
