02

The source-independence model

The evidence rule was wrong, and correcting it is not the same as relaxing it.

A single threshold for every claim is incoherent. "Mozilla shipped a VPN in Firefox", sourced to Mozilla, is not weak evidence awaiting corroboration — Mozilla is the only body that can authoritatively say what Mozilla shipped. Demanding that a third party confirm it first is a category error, not rigour. Meanwhile "the iPhone 18 has a 2nm chip" from one outlet needs corroboration more than the old rule required, because nobody reporting it has any authority over it.

So the requirement is now a function of what is claimed and who claims it.

Claim classIndependent sourcesHow it may be written
First-party announcement1Assertable
Third-party report2Attributed
Unreleased-product claim3Attributed
Rumour or leak1Rumour-framed, never assertable

Note this raises the bar where it matters: unreleased-product claims — the class a technology site is most often wrong about, because the product eventually ships and contradicts you — now need three, where the old flat rule asked for two.

First-party authority is explicitly bounded

This sentence travels on every first-party verdict, rather than living in a code comment: "Authoritative for what was announced and that it was announced. NOT authoritative for performance claims, comparisons with competitors, or anything the announcement predicts. A vendor calling its own product twice as fast is evidence that it said so, not that it is."

Where "who is the subject" comes from: engine_sources.trust_level, which already encoded this and was simply never consulted for it. 28 sources sit at primary — bodies that speak for themselves — and DPReview at secondary, because it reports on other people's products. Nothing is inferred from a name: guessing apple.com from the string "Apple" would hand self-authority to any unverified domain on a substring match. An unregistered domain, a failed read, or a secondary source all yield an empty subject set, which falls back to the strict rule.

Classification runs strictest-first, so first-party authority can never launder a claim a stricter rule already caught — a leak hosted on the vendor's own domain is still a leak.
